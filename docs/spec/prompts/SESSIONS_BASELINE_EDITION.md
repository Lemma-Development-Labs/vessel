# Detailed Build Prompts

Use the common operating contract with every numbered session. The ZIP includes it inside each standalone prompt so it cannot be lost between sessions.

## Mandatory operating contract for every session

You are implementing Vessel in its existing repository. Read AGENTS.md, docs/BUILD_STATUS.md, docs/DECISIONS.md, the latest session checkpoint, and Vessel_Production_Blueprint_v2.md or its canonical copy docs/spec/VESSEL_V1.md before changing code. Inspect git status, current branch, repository structure, deployed manifests, dependency locks and applicable instructions. Preserve unrelated user changes. Reuse correct existing code; do not restart the project or redesign its identity without evidence that replacement is necessary.

Authority: actual chain state and reproducible evidence determine current facts; this v2 blueprint determines intended product policy and explicitly supersedes older conflicting specs. Never treat old tests, memory, a previous report, a screenshot, or a generated answer as evidence that current code works. Start with a concise fact-check table: claim, official URL, checked date, environment, repository/ABI match, chain evidence, and unresolved uncertainty. For current library APIs, use installed package definitions and official documentation. Pin working versions; do not invent methods or addresses. Preserve source links in docs/FACT_CHECKS.md.

Build the complete outcome named in this session, including contracts/services/UI where relevant, meaningful tests, failure behavior, documentation and scoped commits. No production mocks, fake metrics, hard-coded healthy states, silent zero fallback, generic execute escape hatch, TODO in a money-moving path, or broad catch that hides failed work. Simulation fixtures live only in explicit test modules and cannot be imported by mainnet runtime code. No private keys or production credentials in source, browser bundles, logs, screenshots or test fixtures. Use secret references and redact evidence.

Money uses explicit integer units and BigInt/fixed-point math. One shared schema/configuration source serves contracts' generated bindings, SDK, API, app, Terminal, MCP and risk policy. Public data always includes source freshness and environment. Missing, stale, partial, simulated and mismatching evidence stay distinct. Existing USDC testnet, mainnet USDC, and Perpl collateral are different assets until proven otherwise. Perpl testnet market 64 is not a mainnet default.

The v2 decisions are non-negotiable unless amended through a reviewed ADR: USDC deposits; explicit AUSD margin route; one MON market; no publicly redeemable pooled share; custom async requests; Ballast then Reserve then Hull loss order; corrected fee/reserve conservation; one 28-day Hull series; 48-hour junior cooldown; beta transfer restrictions; projected 30% cover admission buffer and 20% intervention floor; independent review before external funds; no vUSD deployment on beta mainnet. Do not silently reinterpret these decisions to fit existing code.

Use a consistent Vessel shell, design tokens, wallet connection, SIWE session, transaction drawer and error vocabulary. Do not introduce a second authentication system or copy economic math into UI components. User wallets authorize user money movements. The public API/MCP cannot reach keeper signing secrets. Keeper permissions, ownership and withdrawal rights are separate and explicitly tested.

If a verified external capability is missing, record the exact blocked feature and evidence needed. Continue independent safe implementation and tests, but do not replace the missing dependency with a mock and call it live. Mainnet deployment, funding, invitations, timelock execution and capital increases are separate release actions requiring the existing explicit operational authorization and passed gates. Never invent a signer or execute a real-money action merely to make a test green. Do not ask for routine implementation preferences when this specification already decides them.

Run meaningful tests of changed behavior and required regression gates, inspect failures, and fix actual causes. Record exact commands, seeds, environment, exit status, transaction references and remaining limitations. Do not claim a test ran if it did not. Stop optional repeated testing after relevant risks and gates are covered. Update docs and BUILD_STATUS in the same feature commits. Use the configured Git author, conventional scoped commit messages, and no Co-authored-by trailers or invented authorship. Do not force-push or rewrite unrelated history. Pushing follows the repository's existing authorization.

At session end provide: completed feature and how to use it; changed modules; architecture decisions; tests and evidence; security findings; live versus simulated status; commit hashes; unresolved gates; and the exact next session/resume instruction. Update docs/sessions/NN.md with the same durable checkpoint. If context ends, resume this session instead of abandoning its outcome. A session can span multiple agent turns. No placeholder completion report.

## Session 2 Economic core and complete local claim lifecycle

Outcome: a user can subscribe to Hull or Ballast, activate a series, observe correct settlement, request an exit, and receive funded USDC in a local adversarial test environment, with production contract boundaries and independent accounting evidence.

Read blueprint Sections 6-10 and 19-20 before coding. Build an independent integer reference model, then implement Solidity against it. Model active A, senior H, junior B, reserve R, fee liabilities, pending deposit escrow, funded claim escrow, external flows and gross loss carryforward L. Prove both the active identity and total physical-custody identity. Price both spot and perp economics exactly once. Donations and previously accrued fee payments cannot become yield. Reserve fee allocation is included in F; conservation uses treasury FT, not full F, alongside change(R).

Specify rounding for every direction: deposits round units down; burns/payouts never exceed funded assets; accrued liabilities round conservatively with a carried remainder; cumulative dust is bounded and assigned explicitly. Coupon uses principal and actual elapsed seconds over 365 days. Add vectors for reserve reaching target, shortfall with positive G, zero gross yield, loss recovery with no fee, reserve depletion and senior impairment. Define deterministic two-pass fee suppression if a proposed settlement would enter impairment, so docs/model/contracts agree.

Implement AssetCustody, TrancheController, HullSeries, BallastToken, RequestQueue, ClaimEscrow, ReserveLedger, BetaAdmission and restricted governance boundaries. Use no external pooled custody share and no public generic ERC-4626 withdrawal bypass. Decide minimal module composition to avoid circular permissions. No upgradeable core proxy. Restrict beta claim transfers to explicitly authorized lifecycle operations. All mint/burn/custody movements reconcile and emit reconstructable events.

Hull: 72-hour segregated subscription window, same fixed terms, one series, no capital deployment before activation, refunds on cancelled/excluded subscriptions, 28-day maturity, no mid-series entry, no early beta liquidity claim and no automatic rollover. Prove activation cannot partially admit a series or price a user differently because of transaction ordering. Freeze a terms hash and validate consent. Implement ordinary maturity and emergency frozen-entitlement wind-down with proportional funded claims and cumulative recovery accounting.

Ballast: protected initial price, seed handling, forward-priced batch admissions, no ordinary recapitalization at zero B, locked-but-exposed exit units, 48-hour cooldown, cancellation, partial funding and exact claim escrow. Settle before admissions/exits. Queue processing is bounded and starvation-resistant. User minimums must not block unrelated requests. Unit/asset conversion in partial processing cannot reset losses or cooldown. Projected cover includes remaining senior coupon and closing costs; enforce 30% admission/payout buffer while treating 20% as intervention, not a magical market-loss prevention invariant.

Enforce reserved pending budget and lifetime gross admitted contribution caps globally and per participant. Failed/refunded never-admitted subscriptions release reservations; withdrawals and losses do not replenish lifetime budgets. Include seed/reserve contributions and prevent direct-token donation capacity increases. Eligibility affects new entry but not holder claims. Test revoked invitation, wallet quota recycling, exempt-token-transfer abuse and all route bypasses.

Implement permissionless settlement only from validated onchain valuation adapters. For this session use explicit test-only deterministic venues/prices with dependency injection and compile/runtime barriers against mainnet selection. Define the production adapter interfaces for Session 3 without claiming live proof. Separate pause dimensions and permit funded claims during ordinary risk pauses. Limit emergency asset destinations.

Acceptance: golden examples match model and contracts; conservation and role invariants survive randomized deposit/exit/loss/recovery sequences; all money paths have malicious-caller tests; full local Hull maturity and junior exit succeed; an insolvency scenario pays holders proportionally with no first-claimer advantage; mainnet caps and disabled lab flags cannot be bypassed. Update ACCOUNTING, STATE_MACHINES, SECURITY and API specifications with actual signatures and events. Commit the core as local complete, not mainnet ready.

Cancel/reconcile before compensation and block all new risk until uncertainty is resolved. Do not sell the entire spot book during a perp outage. Top-ups can only come from permitted unencumbered capital within caps; no unlimited refill of a compromised account. Treat fees and stablecoin conversion PnL consistently with Session 2.

Add deterministic replay tests for crashes at every execution boundary, lost acknowledgements, rate limiting, key revocation and partial fills. Mainnet fork simulations supplement but do not replace real account-path evidence. Produce custody diagrams, risk calibration data, evidence hashes and integration status. Commit only claims supported by actual receipts.
