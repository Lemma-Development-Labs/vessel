## Completed and how to use it

1. **Deploy script** — `contracts/script/DeployV2.s.sol`. Deploys a
   `TimelockController` (default 300 s on testnet, proposer and executor = the
   Safe), `PauseGuardian`, `TrancheController` (which deploys custody, escrow
   and the Ballast token) and a labelled `SimulatedEngine`. It refuses chain
   143 and writes a schema-v1 release manifest to `deployments/<env>-v2.json`.
   Runbook: [../../deployments/README.md](../../deployments/README.md).
2. **`SimulatedEngine`** (testnet only) — `isSimulated() == true`. Its book
   grows only through custody's `credit(amount)`, so a donated token is never
   counted as value. Funding rate is governance-only and bounded.
3. **Governance batches** — `scripts/v2-governance-batch.mjs` turns a spec in
   `deployments/governance/` into Safe Transaction Builder `schedule` and
   `execute` files for the timelock. Specs: `01-wire` (engine, 25,000 dUSD
   stage cap, close cost, 20 dUSD reserve, funding rate), `02-open-series-1`
   (8% rate with a recorded terms hash), `03-allowances` (template).
4. **Keeper journal + policy** — `vessel-service/src/v2/{journal,keeper,policy,runner}.ts`.
   It records each action before sending it and holds a writer lease with a
   fencing token. Each transaction uses a pinned nonce. A timeout counts as
   UNKNOWN (checked later, never resent blindly), and a replaced transaction
   is marked SUPERSEDED. It can only call eight allowlisted controller
   functions. Enable it with `V2_KEEPER_PK`.
5. **`vessel-verify`** — `tools/verify-cli`. A standalone checker that reads
   the chain at one finalized block and checks book identity, custody and
   escrow backing, caps, and units. Exit codes: 0 PASS, 1 MISMATCH,
   2 UNAVAILABLE. The service uses the same code (vendored) for `/v1/book`.
6. **`/v1` evidence API** — `/v1/book`, `/v1/series/:id`,
   `/v1/requests/:id`, `/v1/history`. Every response carries the evidence
   envelope (schemaVersion, environment, chainId, blockNumber, blockHash,
   observedAt, source, units, status). Failures return 503 `STALE_DATA`,
   never a zero.
7. **Event indexer** — `vessel-service/src/v2/indexer.ts` + `indexerLoop.ts`.
   Events are keyed by (chainId, blockHash, txHash, logIndex). On a reorg it
   rewinds, and orphaned rows are marked REVERTED, not deleted. Finality is
   tracked per row. The keeper journal, the indexer and `/v1/history` share
   one database (`DATABASE_URL`, or in-process PGlite off mainnet).

## Architecture decisions

- Testnet governance is Safe `0xe4f2…0279` → TimelockController (300 s). The
  mainnet delay stays 48 h (spec). The guardian can pause only; resuming
  requires governance.
- The testnet short leg is a **SIMULATED** engine, labelled in the contract,
  the manifest and every API response; G01 stays BLOCKED.
- The indexer holds no financial authority: balances come from chain reads,
  and history is a rebuildable projection.
